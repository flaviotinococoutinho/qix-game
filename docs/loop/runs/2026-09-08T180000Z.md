## O que isto diz sobre o mecanismo, não só sobre estas três PRs

A guarda de inventário do `#69` fez o trabalho para que foi feita: apanhou a matriz mentindo, e a
mensagem de falha imprimiu a linha exata a escrever. Mas ela é uma guarda **por árvore**, e o CI é
**por branch**. Enquanto o loop abrir PRs em paralelo que acrescentam testes, o número derivado será
sempre um ponto de encontro obrigatório: *n* PRs paralelas produzem *n(n−1)/2* conflitos garantidos
no mesmo parágrafo, e cada resolução exige rodar a suíte para saber a contagem de asserções.

Isso não é argumento para afrouxar a guarda — derivar continua vencendo vigiar. É argumento para
que o **teto de duas PRs do loop** seja levado a sério como restrição de arquitetura, e não como
etiqueta: o custo de exceder o teto não é revisão mais lenta, é uma resolução manual que só fica
correta com a engine na mão. Com três PRs abertas, esse custo já está posto.
